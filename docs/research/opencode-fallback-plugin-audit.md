# OpenCode fallback plugin audit

**Scope date:** 2026-10-16  
**Target:** WSL2, OpenCode v2.0.30, `opencode run --format json`, multi-iteration goal runner, anonymous `opencode/*` models, and automatic retry after provider 503.  
**Decision:** No audited plugin is safe to deploy as-is for this target. The v2-native candidate is worth forking only after fixing chain advancement and validating replay in a real v2.0.30 process. The stronger-looking mature plugin targets the incompatible v1 API.

## Findings

OpenCode v2 has a different plugin API from v1. At the pinned [v2.0.30 plugin API](https://github.com/anomalyco/opencode/tree/v2.0.30/packages/plugin/src/promise), the plugin surface is Promise-based; the candidate's event subscription, model listing, and session switching methods are supported concepts. The [v2 plugin documentation](https://dev.opencode.ai/v2/docs/plugins/) describes the v2 plugin loader and config. These facts establish API-shape plausibility, not proof that a third-party plugin works with `opencode run --format json`; no candidate was installed or exercised against that CLI in this audit.

The goal runner at [`tools/goal_loop.py`](../../tools/goal_loop.py) launches a fresh executor subprocess for each iteration and captures stdout and stderr together into the executor log. Thus JSON mode output is not isolated from plugin stderr in the evidence file. The v2-native candidate logs to stderr by default, so its log lines can make the captured stream cease to be JSON-lines. `notify: false` avoids those default logs unless a logfile is configured. The runner validates its terminal marker against JSON events if every nonempty line parses as JSON; a plugin stderr line breaks that parse and falls back to text-marker parsing. Do not claim a clean JSON evidence stream until this path is integration-tested.

## v2-native candidate: source-level failure details

The Nabheet plugin's code does match the core v2 mechanism: `session.execution.failed` events include a session ID and error; `ctx.model.list()` supplies model references; and `ctx.session.switchModel()` changes the session's model. Its current source checks only the event's `error.type` and `error.message` with a broad regex; 503 messages matching those fields should trigger, but unrecognized provider error formatting will be missed and broad terms such as `server` can produce false positives.

The chain defect is independently visible in the algorithm and its test cases. The selection code always uses `chain.find(...)` over the configured list. It adds a cooldown only if `switchModel()` throws. After a successful switch, a later failed execution does not exclude the model that just failed, so the same entry remains first and gets selected again. Its fake-context test suite has no multi-model progression case. Set `maxAttempts` to the number of desired failovers only after a patch adds explicit failed/current-model tracking and a test that proves each fallback is attempted once, in order.

`autoRetry: false` (the default) changes the model for a future request but does not retry the failed request, so it is not transparent automatic recovery for a long-running goal step. `autoRetry: true` duplicates the last user instruction in the same session, using text-only extraction. A failed turn may already have executed tools before the provider error; retry can repeat state-changing actions. Attachments, structured prompt parts, and the precise failed tool-call state are not replayed. The README itself calls the prompt replay a state-changing action and keeps it disabled by default.

`ctx.model.list()` means a model is listed by the local OpenCode provider registry; it is not a connectivity/authentication preflight. The source does not call a model to prove it is callable. The candidate does not implement authentication or anonymous access. `opencode/<model>` should only be used if that exact provider/model identifier appears in the local v2 catalog and succeeds in an explicit smoke test; the audit did not verify promo availability, terms, or account-specific access. Anonymous model access is not an entitlement guaranteed by the plugin.

## Recommendation

Do not install any of these plugins into the shared OpenCode runtime now. Keep provider failover at the routing/supervisor layer until it has passed an adversarial v2.0.30 integration test. If retaining a plugin-based path, fork the v2-native candidate and require these gates before use:

1. Patch selection so failed models are excluded/cool down after a provider failure, then test primary -> fallback 1 -> fallback 2 and exhaustion against a real v2.0.30 event stream.
2. Exercise `opencode run --format json` with a simulated provider 503; assert exit/status behavior, captured evidence integrity, and that plugin diagnostics do not corrupt JSON-lines output.
3. Test tool-side effects before failure to ensure retry cannot silently repeat a completed write/action; preserve multimodal/structured input or keep automatic replay disabled and let the supervisor make a new, evidence-preserving attempt.
4. Test a real `opencode/*` model ID for catalog presence, anonymous/auth behavior, 503 behavior, tool calls, and the exact fallback chain. Do not infer availability from a listed model or README example.
5. Pin the reviewed source/tag and package integrity; investigate the v0.1.0 manifest versus v0.1.1 release discrepancy before consuming the npm package.

The repo goal runner already bounds iterations, writes logs/evidence, and separates executor from evaluator. Its iterations run as separate subprocesses, so a plugin's in-memory session counters are not durable goal-level policy. If attempts must be globally bounded across iterations, enforce that in the supervisor and record the selected model and error in evidence.

## Limits

This is source and documentation review, not a runtime test or a security certification. No package was installed, no provider was called, and no anonymous/free-tier availability or provider-side retry semantics were verified. The assessment is specific to OpenCode v2.0.30 and the repository's current goal runner; recheck source tags and package metadata before implementation.
